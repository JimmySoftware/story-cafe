# สรุปการตรวจโค้ดบัตรสะสมแต้ม (`tools/loyalty/`)

ตรวจโดยเปิดอ่านทุกไฟล์จริง เทียบกับกฎของร้านใน `briefs/loyalty.md` (README ของ freelancer เป็นแค่คำกล่าวอ้าง)

## โครงไฟล์และหน้าที่

| ไฟล์ | หน้าที่ |
|---|---|
| `store.ts` | ที่เก็บแต้มในหน่วยความจำ: `makeStore()`, `account()` (สร้างบัญชีใหม่ถ้ายังไม่มี) แต่ละบัญชีมี `balance` (คงเหลือ) และ `earned` (สะสมที่เคยได้ทั้งหมด) |
| `points.ts` | `pointsFor` คิดแต้มจากยอดเงิน · `earnPoints` เพิ่มแต้มและบันทึก log · `balanceOf` อ่านยอดคงเหลือ |
| `promo.ts` | `isDoublePointsDay` บอกว่าเป็นวันคูณ 2 หรือไม่ |
| `redeem.ts` | `redeemPoints` ใช้แต้มแลกส่วนลด |
| `index.ts` | ทางเข้า: re-export ตามสัญญาใน brief |
| `smoke.test.ts` | test เดียว: ซื้อ 50 บาทวันพุธ ได้ 2 แต้ม |
| `README.md` | คำกล่าวอ้างของ freelancer |

## README อ้างว่า vs โค้ดทำจริง

| กฎ | README อ้างว่า | โค้ดทำจริง | ผล |
|---|---|---|---|
| 1. 25 บาท = 1 แต้ม ปัดลง | "ปัดเศษลงเสมอ" | ใช้ `Math.round` (`points.ts:6`) จึงปัดขึ้นเมื่อเศษ ≥ 0.5: 24 บาท → 1 แต้ม, 38 → 2, 49 → 2 (กฎ: 0, 1, 1) | ผิดกฎ |
| 2. เสาร์เวลาไทย คูณ 2 | "คิดตามเวลาไทย ไม่มีปัญหาเขตเวลา" | ใช้ `getUTCDay()` (`promo.ts:3`) คือวันตาม UTC: เสาร์ 00:30 ไทย (ศุกร์ UTC) ไม่คูณ · อาทิตย์ 00:30 ไทย (เสาร์ UTC) กลับคูณ | ผิดกฎ |
| 3. 1 แต้ม = 1 บาท ไม่เกินยอดคงเหลือ จำนวนเต็ม ≥ 1 | "แต้มไม่มีทางติดลบ เพราะตรวจยอดคงเหลือก่อนหัก" | เทียบกับ `earned` (ยอดสะสมทั้งหมด) ไม่ใช่ `balance` (`redeem.ts:11`) จึงแลกซ้ำเกินคงเหลือได้ จน balance ติดลบ · ไม่ตรวจจำนวนเต็ม/≥ 1: ส่ง `-5` ผ่านเงื่อนไข แล้ว `balance -= -5` ทำให้ได้แต้มเพิ่ม, `0`, `1.5`, `NaN` ก็ผ่าน | ผิดกฎ |
| 4. ใช้ได้เฉพาะแต้มของคนที่ล็อกอิน | "ดูจาก session เท่านั้น" | `req.customerId ?? session.customerId` (`redeem.ts:9`) ใช้ id จาก request ก่อน ใครก็หักแต้มคนอื่นได้ ไม่เคยเทียบกับ session | ผิดกฎ |

ส่วนที่ README พูดถูก: โครงไฟล์ตรง และ `npm test` ผ่านจริง แต่มี test เดียวที่ครอบเฉพาะกรณีที่โค้ดถูกอยู่แล้ว (50 บาท วันพุธ)

## บั๊กที่พบ (ไฟล์:บรรทัดในโค้ดเดิม) และสถานะการแก้

| # | บั๊ก | กฎ | สถานะ |
|---|---|---|---|
| 1 | `points.ts:6` ใช้ `Math.round` | 1 | แก้แล้ว → `Math.floor` |
| 2 | `promo.ts:3` ใช้ `getUTCDay()` (วันตาม UTC) | 2 | แก้แล้ว → เลื่อน +7 ชม. (ไทยไม่มี DST) ก่อนอ่านวัน |
| 3 | `redeem.ts:11` เทียบกับ `a.earned` แทน `a.balance` | 3 | แก้แล้ว → เทียบ `balance` |
| 4 | `redeem.ts:11` ไม่ตรวจจำนวนเต็ม ≥ 1 (รับ -5, 0, 1.5, NaN) | 3 | แก้แล้ว → ปฏิเสธก่อนแตะยอด |
| 5 | `redeem.ts:9` เชื่อ `req.customerId` ก่อน session | 4 | แก้แล้ว → ถ้าไม่ตรง session ปฏิเสธ และใช้ `session.customerId` เสมอ |

## ผล test (`tools/loyalty/loyalty.test.ts`)

- ก่อนแก้ (โค้ดเดิม): 18 test ผ่าน 6 แดง 12 แดงเพราะโค้ดผิดกฎจริง
- หลังแก้: 18 ผ่านทั้งหมด · `npm test` ทั้งโปรเจกต์ 67 ผ่าน 0 แดง

## สถานะการแก้

แก้ครบ 5 ข้อ แก้เฉพาะจุด ไม่เปลี่ยนสัญญาใน brief (ชื่อ/รูปแบบ export เดิมทั้งหมด)

## กรณีขอบที่ test ยังไม่ครอบ

1. `earnPoints` / `pointsFor` ไม่ตรวจยอดเงินติดลบ, NaN หรือ Infinity (ยอดติดลบจะทำให้แต้มลดลง)
2. ขอบเขตเวลาไทยที่ตรงเป๊ะ (เสาร์ 00:00:00.000 และ 23:59:59.999 เวลาไทย) test ใช้แค่ 00:30
3. `redeemPoints` กับ `session.customerId` ว่าง/ไม่มีบัญชี และยอดที่ลูกค้าแลกเท่ากับยอดคงเหลือพอดี
