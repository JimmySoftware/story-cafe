# workflow (green-loop) เทียบกับ agent team

> บันทึกจากงาน channel (briefs/channel.md) · ตัวเลขฝั่ง workflow มาจากตารางที่ `tools/green-loop.mjs` พิมพ์จริง · ฝั่ง agent team **ยังไม่ได้ลอง** จึงไม่มีตัวเลข

## ผลรัน workflow จริง
คำสั่ง: `node tools/green-loop.mjs --rounds 3 --part break` (ตัวตรวจ `npm run check -- 23 --part break`)

| รอบ | ข้อที่แดง | ค่าใช้จ่ายสะสม |
|---|---|---|
| 0 (ตรวจก่อนแก้) | 2 | $0.00 |
| 1 (หลังเรียก `claude -p` ครั้งที่ 1) | 1 | $0.21 |
| 2 (หลังเรียก `claude -p` ครั้งที่ 2) | 0 | $0.53 |

สรุป: เขียวหลังแก้ 2 รอบ รวม $0.53 · ไม่หยุดก่อนเขียว · สคริปต์ไม่ได้จับเวลา จึง **ไม่มีตัวเลขเวลา** · `claude -p` ข้างในแก้โค้ดแต่ไม่ได้ commit ให้ ต้องตรวจ diff และ commit เอง

## เทียบกัน

| หัวข้อ | workflow (green-loop) | agent team |
|---|---|---|
| ใครกำหนดจำนวนรอบ | คน (`--rounds`, สูงสุด 6) สคริปต์ตายตัว ไม่ใช่ agent | ยังไม่ได้ลอง |
| เงื่อนไขหยุด | เขียว · ครบ N รอบ · แก้สองครั้งติดกันแล้วแดงรายการเดิมเป๊ะ | ยังไม่ได้ลอง |
| ตัวตรวจ | จำเป็นและต้องชัด/เร็ว (`check --json`) ถ้าตัวตรวจไม่น่าเชื่อ ลูปจะแก้ผิดทางอย่างมั่นใจ | ยังไม่ได้ลอง |
| ค่าใช้จ่ายที่วัดได้ | $0.53 / 2 รอบ (รันนี้) | ยังไม่ได้ลอง ไม่เดาตัวเลข |
| รันใน `claude -p` ได้ไหม | ได้ (เป็นสคริปต์ที่เรียก `claude -p` เอง) | ไม่ได้: ต้องใช้ session แบบ interactive |
| สถานะฟีเจอร์ | เป็นไฟล์ในโปรเจกต์นี้ | **ทดลอง (experimental)** ปิดเป็นค่าเริ่มต้น |

## agent teams (ตามเอกสารทางการ ไม่ใช่ผลที่ลองเอง)
- เป็นฟีเจอร์ **ทดลอง (experimental)** ปิดเป็นค่าเริ่มต้น เปิดด้วย `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`
- ต้องใช้ session แบบ interactive · ใน `claude -p` ไม่ตั้งทีม
- ใช้ token มากกว่า session เดียว
- เอกสาร: https://code.claude.com/docs/en/agent-teams

## ใช้อะไรเมื่อไหร่ (ความเห็นจากงานนี้)
- มีตัวตรวจที่ชัดและเร็ว ขอบเขตงานแคบ → workflow พอ และคุมงบได้ชัด
- งานที่ต้องคุยแบ่งงานกันหลายส่วนแบบ interactive → ค่อยพิจารณา agent team แต่ผมยังไม่ได้ลอง จึงยังเทียบเวลา/รอบ/ค่าใช้จ่ายไม่ได้
