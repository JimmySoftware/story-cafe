## prompt 1 · ชนะ

```text
อ่าน @briefs/open-shop.md, @CLAUDE.md และ @supabase/migrations/20261027000000_sales_summary.sql ก่อน
เป้าหมาย: เจ้าของร้านอยากเห็น "รายงานสิ้นเดือน" ยอดขายรวมทั้งเดือน จำนวนบิล จำนวนแก้ว และยอดแยกรายวัน โดยตัวเลขต้องตรงกับ sales_summary ที่ใช้อยู่ทุกวัน (กติกานับยอดเดียวกัน ห้ามเขียนกติกานับใหม่ซ้ำอีกชุด)
ทำเป็นฟังก์ชัน monthly_sales(p_month date) ใน migration ใหม่ (ห้ามแก้ migration เก่า) เฉพาะพนักงานเรียกได้ วันที่ต้องนับตามเวลาไทย ยังไม่คิด VAT
เขียน test SQL ก่อน แล้วทำจนผ่าน และ npx supabase db reset, npm run test:db, node mine/check.mjs ผ่านทั้งหมด
ตอนท้ายรายงานเป็นภาษาไทยว่าอะไรที่ยังตรวจเองไม่ได้ (เช่น ตัวเลขจากข้อมูลจริงของร้านเดือนที่ผ่านมา)
```

## prompt 2 · ลองพัง

```text
ลองทำให้ monthly_sales พังด้วยข้อมูลแปลก ๆ ก่อนบอกว่าเสร็จ: บิล 00:00 น. วันที่ 1 และ 23:59:59 น. วันสุดท้ายของเดือนตามเวลาไทย, บิลของเดือนก่อนและเดือนถัดไปที่ห้ามถูกนับ, เดือนที่ไม่มีบิลเลย, กุมภาพันธ์ปีอธิกสุรทิน, p_month เป็น null และลูกค้าที่ตั้ง user_metadata.role = staff เอง
เขียนแต่ละกรณีเป็น test ที่ล้มก่อน แล้วแก้ที่ต้นเหตุ ไม่ใช่แก้ให้ test ผ่านด้วยการเดาตัวเลข จากนั้นรัน npm run test:db และ node mine/check.mjs ซ้ำ รายงานตรง ๆ ถ้ากรณีไหนยังพังอยู่
```

## รู้ทันสูตร

- บรรทัด "ตัวเลขต้องตรงกับ sales_summary … ห้ามเขียนกติกานับใหม่ซ้ำอีกชุด" → เป็นบรรทัดสำคัญที่สุด ถ้าไม่บอก Claude มักเขียน query ใหม่ที่นับสถานะออเดอร์ต่างจากเดิม แล้วรายงานเดือนกับยอดรายวันไม่เท่ากัน (สูตรนี้บังคับให้รวมจาก sales_summary และ test เทียบผลรวมรายวันกับยอดเดือน)
- "เขียน test ก่อน" และบอกกรณีขอบเอง → คนมักลืมขอบเวลา: บิลตี 0 ถึงตี 1 ตามเวลาไทยคือวันก่อนหน้าใน UTC ถ้าไม่ระบุ รายงานจะเลื่อนวันและยอดต้นเดือน/ท้ายเดือนผิดเงียบ ๆ
- ข้อผิดพลาดที่พบบ่อย: เปิดฟังก์ชันรายงานให้ทุกคนเรียก เพราะลืมว่าเป็น security definer → สูตรนี้บังคับ "เฉพาะพนักงาน" และลองด้วยลูกค้าที่ตั้ง role เองใน user_metadata
- จุดอ่อนที่สูตรนี้ยังไม่กัน: ตัวเลขถูกต้องตามกติกาของ sales_summary แต่ถ้ากติกานั้นผิด (เช่น นับสถานะที่ไม่ควรนับ) รายงานจะผิดตามไปด้วย และสูตรไม่ได้ให้เทียบกับยอดเงินจริงในลิ้นชัก/ใบแจ้งหนี้ Stripe

## ตรวจ

`node mine/check.mjs` ตรวจกับฐานข้อมูลในเครื่อง (ต้อง `npx supabase start` และ `db reset` ก่อน) แล้วพิมพ์ ✓/✗ เป็นภาษาไทยทีละข้อ ผ่านแล้วพิมพ์ "ผ่านทั้งหมด" และ exit 0:
1. มีฟังก์ชัน `monthly_sales(date)` ที่ตั้ง `search_path`
2. anon เรียกไม่ได้ และลูกค้าที่ตั้ง `user_metadata.role = staff` เองถูกปฏิเสธด้วย `forbidden`
3. พนักงานเรียกแล้วได้ยอดเดือน = ผลรวมรายวัน, ขอบวัน/ขอบเดือนตามเวลาไทยถูก, ไม่นับเดือนอื่น, กุมภาพันธ์ปีอธิกสุรทิน 29 วัน
4. ข้อมูลทดลองทั้งหมดถูก rollback ไม่ทิ้งอะไรไว้ในฐาน
