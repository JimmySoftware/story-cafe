# Brief: บัตรสะสมแต้ม (กฎของร้าน) — ใช้ตรวจโค้ดที่ freelancer ทิ้งไว้ใน tools/loyalty/
> ข้อมูลสมมติเพื่อการเรียน · freelancer เขียนโค้ดไว้ใน `tools/loyalty/` พร้อม README ที่บอกว่า "ผ่านทุกอย่างแล้ว" แต่ไม่มีใครตรวจ · กฎด้านล่างคือความจริงที่เจ้าของร้านต้องการ

## กฎ (เจ้าของร้านเขียนเอง)
1. ซื้อทุก **25 บาท ได้ 1 แต้ม ปัดเศษลง** (38 บาท = 1 แต้ม · 49 บาท = 1 แต้ม · 50 บาท = 2 แต้ม · 24 บาท = 0 แต้ม)
2. **วันเสาร์ตามเวลาไทย (Asia/Bangkok) แต้มคูณ 2** — ดูจากวันที่ตามเวลาไทยของเวลาที่ซื้อ ไม่ใช่เวลา UTC (เสาร์ 00:30 เวลาไทย = ได้คูณ 2 · อาทิตย์ 00:30 เวลาไทย = ไม่คูณ)
3. ใช้แต้มแลกส่วนลด **1 แต้ม = 1 บาท** ต้องเป็นจำนวนเต็ม ตั้งแต่ 1 ขึ้นไป และ **ไม่เกินยอดคงเหลือ** (แต้มห้ามติดลบ ห้ามได้แต้มเพิ่มจากการ "ใช้แต้มติดลบ") · ถูกปฏิเสธแล้วยอดต้องไม่เปลี่ยน
4. **ใช้ได้เฉพาะแต้มของคนที่ล็อกอิน** (`session.customerId`) — ถ้า request ส่ง `customerId` ของคนอื่นมา ต้องปฏิเสธ (`ok: false`) และแต้มของเขาไม่เปลี่ยน

## สัญญาที่ห้ามเปลี่ยน (ตัวตรวจและ test เรียกตามนี้)
`tools/loyalty/index.ts` ส่งออก: `makeStore()` · `earnPoints(store, customerId, amountBaht, when?) → จำนวนแต้มที่ได้` · `balanceOf(store, customerId)` · `redeemPoints(store, session, request) → {ok:true,balance,discountBaht} | {ok:false,error}` · `pointsFor` · `isDoublePointsDay`
test ทุกไฟล์ต้อง import จาก `./index.ts` เท่านั้น (เพื่อให้ตัวตรวจเอา test ไปลองกับโค้ดต้นฉบับได้) และใช้ `node:test` เหมือน `smoke.test.ts`

## วิธีทำงานกับโค้ดที่ไม่ได้เขียนเอง
1. อ่านไฟล์จริงทุกไฟล์ก่อน — **README เป็นแค่คำกล่าวอ้าง** ไม่ใช่หลักฐาน
2. เขียน test ให้ **แดงก่อนแก้** (ล้มเพราะโค้ดผิดกฎจริง ไม่ใช่เพราะ test เขียนผิด) ครอบกฎทั้ง 4 ข้อ
3. แก้ทีละบั๊กให้ test เขียว ไม่เขียนโค้ดใหม่ทั้งหมด ไม่เปลี่ยนสัญญาด้านบน
4. สรุปลง `docs/loyalty-summary.md`: โครงไฟล์ · หน้าที่ของแต่ละไฟล์ · ตารางเทียบ "README อ้างว่า" กับ "โค้ดทำจริง" ทีละกฎ · บั๊กที่พบ (ไฟล์:บรรทัด) · สถานะการแก้
