# Brief: caption IG / TikTok ของเมนูประจำฤดู
> ข้อมูลสมมติเพื่อการเรียน · ชื่อในนี้คือข้อตกลงที่ `npm run check -- 17` อ่านตามเป๊ะ · ไม่ต้องสมัครหรือใส่ key อะไร: ใช้ล็อกอินของคุณเองที่ `claude` ใช้อยู่แล้ว

## เป้าหมาย
เมนูประจำฤดูอยู่ใน `data/seasonal.json` (ชื่อ ราคา คำบรรยายสั้น ๆ) ร้านอยากได้ caption สำหรับโพสต์ Instagram และ TikTok แบบที่ **ตรวจได้ ไม่ใช่ข้อความลอย ๆ**: ทุกครั้งที่รันต้องได้ JSON ที่หน้าตาเหมือนเดิมเสมอ เพื่อให้ขั้นต่อไปของร้านเอาไปใช้ต่อได้โดยไม่ต้องมีคนอ่านทุกบรรทัด

## เครื่องมือ `tools/caption/`
รันด้วย `node --import tsx tools/caption/cli.ts [--out <ไฟล์>]` (ค่าเริ่มต้น `out/captions.json`)
1. อ่าน `data/seasonal.json` (ห้ามพิมพ์ชื่อหรือราคาเมนูซ้ำในโค้ด)
2. เรียก Claude ด้วย `claude -p` แบบ **ไม่ใช้ shell** (ส่ง argument เป็นอาร์เรย์): `<CLAUDE_BIN> -p <prompt> --output-format json --json-schema <schema>` โดย `CLAUDE_BIN` อ่านจาก env (ค่าเริ่มต้น `claude`) · ผลที่ใช้คือฟิลด์ `structured_output` ของ JSON ที่ได้กลับมา
3. **schema** (ส่งให้ `--json-schema`, ต้องเป็น JSON ที่ parse ได้): `{"captions": [ {"platform": "instagram" | "tiktok", "text": string, "hashtags": [string] } ]}` จำนวน caption = 3 พอดี
4. **กติกาของผลลัพธ์** (ตรวจในโค้ดเราเอง ไม่เชื่อโมเดลลอย ๆ) ที่ `tools/caption/validate.ts` ส่งออก `validateCaptions(data, seasonal)` คืน `{ ok: boolean, errors: string[] }`:
   - มี caption 3 อัน, มีทั้ง `instagram` และ `tiktok` อย่างน้อยอย่างละ 1
   - `text` ยาว 20–200 ตัวอักษร, เป็นภาษาไทย (มีอักษรไทย), กล่าวถึงเมนูประจำฤดูอย่างน้อย 1 เมนูโดยใช้ **ชื่อตรงกับไฟล์**
   - `hashtags` 3–8 อัน ขึ้นต้นด้วย `#` ไม่มีช่องว่าง
   - ราคาที่ปรากฏใน `text` (ตัวเลขที่ตามด้วย `บาท` หรือ `฿`) ต้องเป็นราคาจริงของเมนูในไฟล์ · ห้ามอ้างเรื่องสุขภาพ (`รักษา`, `ลดน้ำหนัก`, `ดีต่อสุขภาพ`)
5. ถ้าผลไม่ผ่านกติกา: **ลองใหม่อีก 1 ครั้ง** โดยบอกโมเดลว่าผิดข้อไหน · ถ้ายังไม่ผ่าน → **ไม่เขียนไฟล์ผลลัพธ์** พิมพ์ข้อความภาษาไทยที่อ่านรู้เรื่อง (บอกข้อที่ผิด) และ exit code 1
6. ถ้า `claude` เรียกไม่ได้หรือยังไม่ได้ล็อกอิน: exit code 2 พร้อมข้อความไทยบอกให้เปิด `claude` แล้วพิมพ์ `/login` (ห้ามโชว์ stack trace)
7. สำเร็จ: เขียนไฟล์ (สร้างโฟลเดอร์ให้ถ้ายังไม่มี) พิมพ์ `สร้าง caption 3 อัน → <ไฟล์>` exit 0
- ชื่อเครื่องมือในข้อความที่ร้านเห็น (คำสั่งช่วยเหลือ ข้อความ error ชื่อในไฟล์ผลลัพธ์) ห้ามเรียกว่า "Claude Code" (ร้านเรียกว่า "ตัวช่วยเขียน caption")

## ส่วนตัว vs ให้บริการผู้อื่น (เส้นที่ต้องรู้)
- ใช้กับร้านของคุณเอง ในเครื่องของคุณ ด้วยล็อกอินของคุณ = **ใช้ส่วนตัว** ได้
- ถ้าจะทำเป็นบริการให้ร้านอื่นใช้ (เช่น SaaS) ต้องใช้ **API key** ของบริการนั้นเอง ไม่ใช่ล็อกอินส่วนตัวของคุณ
- โค้ดอ่านโหมดจาก env: ถ้ามี `ANTHROPIC_API_KEY` = โหมด api-key ไม่มี = โหมด login · `tools/caption/auth.ts` ส่งออก `checkAuth(env)` คืน `{ mode: 'login' | 'api-key', keyOk: boolean | null }` (`keyOk` ตรวจแค่ **รูปแบบ** ว่าขึ้นต้น `sk-ant-` และยาว ≥ 20 ตัว ไม่ได้ยิงเน็ต; โหมด login = `null`)
- `node --import tsx tools/caption/cli.ts --auth-check` พิมพ์บรรทัดภาษาไทยบอกโหมด (และถ้าเป็น api-key บอกว่ารูปแบบ key ใช้ได้/ไม่ได้) · **ห้ามพิมพ์ key ออกมาทุกกรณี** (ทั้งเต็มและบางส่วน) · exit 0 เมื่อโหมด login หรือ key รูปแบบถูก, exit 1 เมื่อ key รูปแบบผิด
- `.env.example` มีบรรทัด `ANTHROPIC_API_KEY=` (ค่าว่าง) มาให้แล้ว (กฎตู้เซฟบท 3 ห้าม Claude อ่าน/แก้ไฟล์ `.env.*` — ถ้าต้องแก้ ให้คุณแก้เอง) แล้วเขียน `docs/personal-vs-service.md` อธิบายเส้นนี้สั้น ๆ (คำว่า "ส่วนตัว", "ให้บริการ", "API key") พร้อมลิงก์เอกสารทางการ: https://code.claude.com/docs/en/legal-and-compliance
- key จริงห้ามอยู่ในแชทหรือไฟล์ที่ commit: key ทดสอบในโค้ดต้องเป็นของปลอมที่ดูปลอม (`sk-ant-FAKE-…`)
