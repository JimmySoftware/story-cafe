# Brief: คำสั่ง /ship ของร้านเรา
> ข้อมูลสมมติเพื่อการเรียน · slash command ที่เจ้าของร้านสั่งตอน "งานนี้พร้อมส่งหรือยัง" ให้ Claude ไล่ตรวจเป็นขั้น ๆ แล้ว commit ให้

## ผลที่ต้องได้
ไฟล์ `.claude/commands/ship.md` (เข้า git ไปกับทีม) ที่พิมพ์ `/ship` แล้ว Claude ทำตามลำดับนี้ **ทุกครั้ง ไม่ข้ามขั้น**:
1. **สำรวจ** — `git status` และ `git diff --stat` บอกว่าแตะไฟล์อะไรบ้าง ถ้ามีไฟล์ที่ไม่เกี่ยวกับงาน (เช่น `.env`, ไฟล์ชั่วคราว) ให้หยุดและถาม
2. **แผน** — บอกสั้น ๆ ว่าจะตรวจอะไรและ commit อะไร
3. **ลงมือ** — ถ้ามีข้อที่ตกในขั้นถัดไป แก้เฉพาะสิ่งที่ตก ไม่ทำเกินงาน
4. **พิสูจน์** — รันครบและรายงานผลจริง: `npm test` · `npm run test:db` · `cd web && npm run build` · `node tools/rls-probe.mjs` (ตรวจว่าลูกค้าคนหนึ่งเห็นข้อมูลของอีกคนไม่ได้) · ถ้าข้อไหนรันไม่ได้ให้บอกว่าไม่ได้ตรวจ ห้ามบอกว่าผ่าน
5. **commit** — ข้อความภาษาไทย ระบุชื่อไฟล์ทีละไฟล์ ห้าม `git add -A` / `git add .` ห้าม push (ตามกฎร้าน)
ถ้าขั้น 4 มีข้อตกที่แก้เองไม่ได้ในขอบเขตงาน ให้หยุดที่ขั้น 4 และรายงาน ไม่ commit

ไฟล์ต้องมี frontmatter `description:` (ภาษาไทย 1 บรรทัด) และเรียกใช้ได้ทั้งใน session ปกติและ `claude -p "/ship"`

## เสร็จเมื่อ
- มี `.claude/commands/ship.md` ตามนี้ และ `CLAUDE.md` บอกว่ามีคำสั่ง /ship
- รัน `/ship` แล้วได้รายงานครบ 5 ขั้นเป็นภาษาไทย
